# HBC C source review

Review date: 2026-10-07
C source: `C-sources/hbc/channel/channelapp/source`
Rust source: this `hbc-rs` crate

This review compares each in-scope ledger reference with its Rust counterpart. `config/parity-ledger.csv` remains the status source; this file records review evidence and findings. `source_reviewed` means the comparison is recorded. It does not mean hardware behavior is verified or that partial behavior is complete.

## Findings

- **HBC-GX-01 — footer vertex format:** The empty-browser footer submitted textured vertices while GX still used the solid descriptor. The shared video draw methods now select the descriptor before every format transition. The same Dolphin controller sequence produced 2,360 invalid-opcode reports in revision `aafde21` and zero with fix `49782bd`. See [the source comparison and captured evidence](hbc-gx-footer-2026-10-07.md). Real Wii checks remain pending.

### C runtime comparison supplied on 2026-10-07

The user supplied a C `channelapp-channel.dol` screenshot that shows an empty browser, a Wii Remote hand pointer, bubbles, and the network/USB Gecko status art. Its Dolphin log contains the same missing playtime file and BootMii metadata results (`-106`) as the Rust run. These missing files therefore do not explain the different initial screen. This is user-supplied runtime evidence plus source comparison; no new matched-profile C/Rust emulator run was performed for this review.

- **HBC-STORAGE-01 / HBC-UI-02 — no-storage notice and Options probe:** C `source/appentry.c` `ae_func` attempts the preferred device and fallback devices. The supplied C screenshot shows the empty browser after any no-storage notice has been dismissed. Rust `WiiStartup::poll_storage_scan` shows the no-storage notice after the first completed empty scan. Pressing OK, Back, or Home returns to the browser, and repeated scans do not reopen an unchanged missing-storage notice. Dolphin exposed an Options probe loop: `device_is_inserted` returned `Fat(Io)` when device startup failed because it then called shutdown on an interface that had not started. C records unavailable and continues without shutdown in this case. `ogc-fat` now follows that order; after a successful start it still propagates a failed shutdown. The HBC probe maps `DeviceUnavailable` and `MediaRemoved` to unavailable, while other errors remain visible. Host tests cover those paths. The production Dolphin run verifies the no-storage dialog, Options remaining open across repeated probes, return to the browser, and zero GX opcode errors. Captures are in `target/gx-footer-options-final/`; Wii checks remain pending.
- **HBC-UI-02 — Options button lettering:** Dolphin showed availability captions over device-button labels and clipped long labels because the frame used an oversized character-width estimate. Rust now uses the selected font size to fit button labels, removes the overlapping captions, moves the sort caption clear of its buttons, and gives Network setup a button wide enough for its label. Host rendering tests check full device and network labels and confirm the captions are absent. The final Dolphin Options capture shows complete button labels without the error dialog; verify theme-font variants on Wii hardware.
- **HBC-DATA-02 — confirmed startup error-presentation gap:** C `source/playtime.c` `playtime_destroy` logs the failed open and returns. Rust `src/main.rs` now reports the failed reset through `ogc_system::report` and keeps the startup screen available. The operation resets the correct four-byte prefix. Host tests verify larger records preserve all bytes after that prefix. Wii persistence verification remains pending. Do not create or patch NAND files to hide this difference.
- **HBC-STORAGE-01 — mount and recovery error preservation:** Rust `mount_preferred_volume` records each mount result, continues the fallback scan, and distinguishes `DeviceUnavailable` from FAT or transport failures. A real mount failure is reported; failed app-install recovery now reaches the startup result and a visible error notice instead of an empty catalog. Catalog scan and shutdown errors also retain details. Verify these error paths with controlled Dolphin storage and confirm fallback behavior.
- **HBC-INPUT-02 — pointer backend needs follow-up:** C and Rust both select the first valid IR owner, use buttons/accelerometer/IR reports, configure a viewport padded by 128 pixels, and subtract 64 from each pointer axis. Rust also submits pointer art when a pointer is available, including on a notice screen. No missing application-level pointer draw path was confirmed. If the Rust pointer remains absent with the same mouse position and controller profile, inspect the production Bluetooth/WPAD handshake, report mode, IR validity, and event delivery. The two screenshots alone do not identify that backend failure.
- The C `/shared2/sys/NANDBOOTINFO` request belongs to libogc's launch support. The `00000200` title check is C `title.c` `is_vwii`. Both can produce missing-file logs. C's explicit startup IOS reload is inside `#if 0`; this source does not support enabling a new IOS reload as a fix.


- **HBC-UI-02 / HBC-STORAGE-01 — notice dismissal:** A replacement notice preserves the original return screen. Completed storage scans track device presence and show an unchanged no-storage result only once. A mounted-to-missing transition reports removal. Device probes classify absent devices as unavailable and keep real probe errors visible. Host regressions cover replacement notices from browser and details, all three dismissal inputs, repeated missing scans, device return/removal, and probe-error handling. The user screenshot shows the C browser after dismissal. A production Rust Dolphin run verifies notice dismissal, Options remaining open through repeated unavailable-device probes, and return to the browser with emulated GameCube controller input; Wii checks remain pending.

- **HBC-DATA-02 — playtime record reset:** C calls `playtime_destroy()` before settings load. The Rust path now opens the same System Menu file, requires at least four bytes and preserves the remaining file bytes, writes four aligned zero bytes, checks every ISFS and close result, then reopens and verifies the stored bytes. If reset fails, HBC logs the failure and continues, as C does. Host tests exercise the shared reset and read-back sequence, including a 128-byte file whose remaining 124 bytes stay unchanged. Files shorter than four bytes are rejected. Wii persistence verification remains pending.
- **HBC-INPUT-01 — extension actions and screenshots:** `config.h` enables `ENABLE_SCREENSHOTS`. C maps Nunchuk Z/C and Classic ZR/ZL to the network-init and screenshot signals, then reads the completed EFB and saves `/hbc-000.png` through `/hbc-999.png`. Rust now maps the same signals, captures the EFB after GX drawing completes, encodes the RGBA pixels as PNG, and writes the first unused name on the selected mounted volume. Allocation, capture, PNG, and FAT errors reach the user as an error notice; failed partial writes are removed when possible and cleanup errors are preserved. Host tests cover button mappings, chord gating, PNG pixels and validation, and filename collision/error behavior. Dolphin and Wii capture and file-output verification remain pending.
- **HBC-THEME-01 / HBC-ZIP-02:** the source requires a root `theme.xml` and accepts only recognized root theme assets. Rust validation now enforces those rules. Existing bounds and supported compression checks remain explicit in Rust.
- **HBC-CATALOG-01 — catalog scan:** Rust now streams directory entries instead of copying the full directory into memory. It scans past non-app entries and stops after C HBC’s 1024 valid-app limit. File-operation errors include their paths, and directory readers close on success and failure. Missing or malformed optional metadata and invalid icons do not hide a valid app.
- **HBC-THEME-02 — font selection and refresh:** Rust now loads HBC’s bundled Droid regular and bold faces, applies C HBC’s per-target default sizes, and falls back to the matching bundled face when a theme font cannot be loaded. Theme application replaces the live texture/font set with the validated package. Wii visual checks remain pending.
- **HBC-LOCALE-01 — translated strings:** Rust now generates its six runtime catalogs from the six C PO files. The generator checks all message keys and translations. Rust-only extension labels still use the local fallback table.
- **HBC-THEME-02 / HBC-THEME-03 — widescreen background:** C loads only `background_wide.png` for a theme in widescreen mode, then falls back to the built-in wide image. Rust previously used a theme `background.png` when the wide image was absent. Rust now selects the wide theme asset only and falls back to the built-in wide image, with a host regression test for the production asset-selection helper. Other texture dimensions and hardware output remain under review.
- **HBC-SETTINGS-01 / HBC-SETTINGS-02:** C settings I/O uses direct ISFS reads and delete-then-create writes. Rust validates XML, checks exact read/write results, and uses staged replacement and recovery. These are deliberate safety improvements; they preserve the settings contract while avoiding deletion of the last valid copy on a failed write.
- **HBC-DATA-01:** C obtains the running title's ES data directory. Rust obtains the same directory, validates the returned buffer, caches it, and builds bounded file paths.
- **HBC-BOOT-01 / HBC-BOOT-02 / HBC-SYSTEM-01:** startup order, the frame loop, and exit paths were compared. Rust owns failures and cleanup explicitly. Remaining screen and event differences are recorded as partial coverage; system calls still require Wii verification.
- **HBC-STORAGE-01 / HBC-STORAGE-02 / HBC-STORAGE-03 / HBC-CATALOG-01 / HBC-DELETE-01:** device startup, scan/refresh, SD Gecko call order, app metadata scan, and deletion were compared. The port covers the tracked paths; asynchronous scheduling and adapter, FAT rename, and hot-removal behavior remain subject to the ledger's follow-up or hardware checks.
- **HBC-INPUT-02 / HBC-VIDEO-01 / HBC-GX-01 / HBC-THEME-02 / HBC-THEME-03 / HBC-UI-01 / HBC-UI-02 / HBC-ANIMATION-01 / HBC-LOCALE-01:** C coordinate, display, scene, theme, widget, dialog, animation, and language behavior was compared with the corresponding Rust paths. The browser no longer paints Rust-only header/footer bands over the full-screen HBC background, and it omits missing app icons as C does. Storage scanning uses the full scene background instead of a solid panel. Remaining visual and controller checks are runtime verification on Dolphin and Wii.
- **HBC-BOOTMII-01 / HBC-BOOTMII-02:** title marker detection and the IOS 254 action path were compared. The detection and launch code paths are implemented. IOS 254 launch and return behavior still require Wii verification.
- **HBC-WIILOAD-01 / HBC-WIILOAD-02 / HBC-ZIP-01 / HBC-INSTALL-01 / HBC-INSTALL-02:** C receive, header, archive classification, extraction, and replacement paths were compared. Rust validates inputs and reports operation and cleanup failures. Socket/USB transport, FAT rename and recovery behavior remain subject to Wii verification.
- **HBC-LOAD-01 / HBC-LOAD-02 / HBC-LAUNCH-01:** C DOL/ELF relocation and launch handoff were compared with Rust validation, staging, and transfer. Rust checks ranges and reports recoverable failures. The launch code is implemented with the documented fail-safe return when AHB patching or IOS reload fails. Verify the handoff on Wii hardware.

The Rust-only network profile editor and scan, and the incomplete optional update/installer path do not have complete C HBC behavior to match. Their ledger rows remain partial and list open work; they are not reported as complete parity.

## 2026-10-07 Dolphin startup and rendering follow-up

The production HBC DOL now renders glyphs with partial GX tiles. Texture creation failures are returned, textured quads map image rows to the matching screen rows, and all owned GX texture buffers are cache-flushed by their shared constructor. The storage worker now completes its FAT mutex operations because LWP synchronization objects use one-based handles, separate from complemented-pointer thread handles. Host regression tests cover partial tile padding, texture orientation, and synchronization handle bounds.

An isolated Dolphin run of the release DOL completed storage discovery across SD, USB, and both GameCube memory-card slots. With no emulated SD or USB volume configured, the DOL displayed the Rust no-storage notice. The C runtime comparison above shows that this initial notice differs from C. A direct read from Dolphin's XFB showed legible dialog text and normally oriented artwork. Wii hardware checks remain pending.

## 2026-10-08 menu, options, and About parity follow-up

Compared C `controls.c`, `controls.h`, `main.c`, `dialogs.c`, `m_main.c`, and `view.c` with Rust input mapping, `AppController`, and frame layout.

- C opens Options with GameCube X or Wii Remote 1 (`PADS_1`); GameCube Y or Wii Remote 2 (`PADS_2`) changes browser mode. Rust mapped these actions the same way. Added Classic Controller mapping regressions to protect the X/Y distinction.
- C's main menu uses Back, About, optional Launch BootMii, Exit to System Menu, and Shutdown. Rust uses the same order and omits BootMii when unavailable. Main-menu focus now responds only to Up/Down. C's version and IOS labels are present in the right-aligned top column; network status uses the live Wiiload address when available.
- C Options starts focused on Back and uses enabled-widget movement. Rust starts on Back, keeps C-style enabled horizontal movement, and uses the visible row geometry for vertical movement. The added Network setup item sits between sort and bottom controls and can be selected by moving up from Back or down from the sort controls. Device availability gates the original device controls.
- The original Options device labels, device rows, sort label and buttons, and bottom buttons now use the C dialog coordinates. The added Network setup control uses the existing gap between sort and bottom buttons.
- Rust About now uses C's credit wording and order, inserts translated credit and active-theme description at the same points, and removes the extra return hint. C starts automatic scrolling after 120 frames and advances one line every three frames. Rust already used that delay and speed; this pass added a regression proving manual Up/Down scrolling still works while automatic scrolling runs.
- The Rust-only network settings use a directional graph that follows their row and column layout. The scan list uses Up/Down, and the keyboard keeps spatial row/column navigation. Password entry now has a controller-selectable Show/Hide control; it is masked by default.
- Error notices now close after 300 update frames without input or on any controller button press. Other notices keep their existing dismissal behavior. The loading throbber remains tied to active storage work; it does not claim that a still-running scan has finished.

`cargo fmt`, `cargo test --lib`, and host `cargo check --all-targets` pass (242 tests). One host dead-code warning in `src/platform/nand.rs` was fixed by compiling its attributes type only where the replacement backend is available. The Wii custom-target build passes. Hardware rendering and controller behavior remain unverified in this pass. Network setup and scanning remain Rust extensions without a C HBC counterpart.

## 2026-10-08 default theme fallback parity

C `theme_init(NULL, 0)` attempts to read `theme.zip` from the channel data directory. When it cannot load an installed archive, it selects the built-in default theme without opening a warning dialog. Rust now follows that visible behavior for theme read and parse failures. It keeps the real failure in the system log and uses its validated built-in theme assets. A malformed installed archive still falls back as a whole, which is safer than C's partial theme mutation. The `-101` ISFS detail from the recent Dolphin warning remains available in the log for diagnosis.

C also continues with default settings when its settings load fails. Rust keeps settings persistence disabled after a failed read, so it cannot overwrite settings that it did not read successfully; this is a deliberate safety difference. Rust still shows the settings failure as a five-second warning.

The theme fallback is no longer a runtime warning, while real settings read failures remain visible for five seconds. Source comparison is complete; verify the updated default-theme startup screen and settings persistence on Wii hardware.
